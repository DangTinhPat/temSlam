# RGB–ToF calibration in simulation

Run from the workspace root:

```bash
MUJOCO_GL=egl python3 technology/scan3d_fusion/calibration/sim_plane_calibration.py
```

Requires the existing Python packages MuJoCo, NumPy, SciPy and PyYAML. The default model is `indoor_tiny_house.xml`; output can be changed with `--output`.

The script ray-casts synthetic camera depth points and noisy 8×8 ToF ranges from the same MuJoCo scene. It collects eight front/oblique wall and floor viewpoints, fits a ToF plane for each sample, then uses robust SE(3) least squares to map camera-frame points onto the corresponding ToF planes. MuJoCo geom IDs provide the plane correspondence labels, analogous to manually marking plane segments in the DELTAR calibration procedure.

The run produced:

- Rotation error against the hidden MuJoCo mount transform: **0.32°**.
- Translation error: **0.91 mm**.
- Median absolute point-to-plane residual: **23.0 mm before**, **3.6 mm after** calibration.
- Point-to-plane RMSE after calibration: **7.4 mm**.

Results and source observations are in `datasets/processed/sim_rgb_tof_calibration/`. `calibration_result.json` contains the estimated camera-to-ToF transform, simulation truth for validation, and metrics; `calibration_observations.npz` contains the camera points and ToF planes used by the solver. The transform maps points expressed in the camera frame into the ToF frame.

This checks the geometric calibration solver with the simulator's configured ToF noise. It does not calibrate physical hardware: camera depth is generated by exact scene ray casts, plane correspondences come from simulator labels, and the real ToF histogram/distribution is not modeled. It also does not test RGB visual odometry or DELTAR inference.
