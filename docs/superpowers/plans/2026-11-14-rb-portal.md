# RB Portal Implementation Plan

**Goal:** Deliver the approved interactive project portal with durable document publishing.
**Architecture:** Flask + SQLite for curated content and admin uploads; plain browser modules and Three.js for the interface and real scan playback.
**Spec:** docs/superpowers/specs/2026-11-14-rb-portal-design.md

## Constraints
Preserve existing report and all robot/SLAM code. Use measured data with provenance. No fake live feeds. All assets self-hosted. Uploads and credentials remain out of Git. Default host 127.0.0.1.

## Tasks
- [x] Content/API: create app.py, prepare_content.py, tests/test_app.py, requirements.txt. Tests exercise authentication, CSRF, draft visibility, upload validation, persistence, safe Markdown and asset isolation. SQLite documents expose id/title/summary/category/tags/kind/published; API detail includes sanitized HTML or media URL.
- [x] Portal: replace index.html after copying report-legacy.html; add static/app.css, app.js, viewer.js and admin.js. Six routes plus document detail. Three.js loads only real mesh/trajectory assets. Controls include orbit/reset/top view/layers/play/pause/seek. Library search and category filters operate on published metadata; admin endpoints require session and CSRF.
- [x] Content packaging: copy curated Markdown and report illustrations into content and public assets; rewrite internal links to portal documents/assets or plain source references. Export compact trajectory JSON without absolute paths; copy mesh. Re-running packaging must not overwrite uploaded content or user metadata.
- [x] Validation: run isolated backend tests; inspect desktop/mobile browser renders and interaction flows including an actual upload, publish, reload and unpublish. Review code independently and fix findings. Record evidence and remaining deployment limitations in QA.md; document setup/run/password provisioning in README.md.
