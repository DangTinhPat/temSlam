# Clean SLAM Obstacle Map Implementation Plan

> **For agentic workers:** Use the existing three-person product team and execute one reviewed slice at a time. Do not spawn additional agents. Implementation follows the applicable development/verification skills; user authorization already covers the staged work. No commits or pushes.

**Goal:** Deliver an independently evaluated 3D obstacle map from measured RGB and ToF fusion, with confirmed floor excluded, uncertain geometry preserved separately, and no accepted discontinuity from tracking, matching, or loop closure.

**Architecture:** Track continuous synchronized RGB/fusion-depth measurements with cuVSLAM; validate local visual motion against synchronized wheel/IMU and camera mount, while accepting the complete optimized global trajectory with one initial alignment. Classify measured geometry using time-matched physical wheel/IMU gravity and calibrated camera mount; retain camera-frame label provenance and place those observations using final optimized SLAM poses. Export obstacle, uncertain, and ground evidence separately. Build the conservative navigation grid from original measurements and labels, never from a cosmetically cleaned mesh.

**Tech Stack:** Existing Python, NumPy/SciPy, MuJoCo, DELTAR, cuVSLAM 17.0.1, existing reconstruction and navigation modules. No new dependencies.

**Spec:** This document, especially “Product contract and acceptance.” It extends the existing 2026-11-14 SLAM-loop and ground-segmentation plans.

## Global constraints

- Preserve all existing dirty changes and raw datasets. Use new output directories; never overwrite accepted/baseline artifacts.
- Simulator pose/geometry belongs to rendering and separate offline evaluation. No truth pose, true depth, floor plane, or fitted trajectory alignment enters a production estimator, reconstruction, controller, or map candidate. The tightly isolated diagnostic exception below never produces an acceptable candidate.
- Retain original RGB, supported fusion depth, timestamps, wheel/IMU packets, and per-frame mount. Never invent neck positions or substitute odometry poses to continue a broken map.
- Local motion validation must use local visual odometry, never differences across globally optimized poses. Global loop closure is not rejected just because its correction is large.
- Zero/invalid depth is missing evidence. Unknown is never free. Removing confirmed floor must not erase low obstacles or ambiguous observations.
- No whole-repository refactor, dependency replacement, full-route rerun before short tracking passes, or tuning thresholds against a preferred GPU run.
- User sensor constraint is fixed: **one RGB camera + one 8x8 ToF**, retaining existing physical IMU/encoder capability. No stereo or replacement dense-depth hardware.
- Exactly three persistent roles: product/planning (this document), coding (implementation), independent review/test. Root coordinates and owns GPU experiments. Use the same roles for subsequent cycles.

## Product contract and acceptance

Acceptance thresholds below are engineering targets for this simulation, not existing measured results or hardware calibration. Report every run, including failures. No scale fitting. First-pose alignment is primary on the nearly straight initial segment; unconstrained SE3 trajectory fitting is secondary because straight-line position alignment is orientation-degenerate.

### Gate A: ten-second tracking feasibility only

All three repeats must meet these limits on the same 150 immutable measurements:

| Requirement | Limit |
|---|---|
| Provenance | No oracle input, unchanged timestamps/depth/mount, all requested timestamps accounted for |
| Native coverage | 150/150 valid tracked frames; no substituted pose, no rejected frame, no input gap > 0.08 s |
| First-pose aligned translation | RMSE <= 0.05 m; maximum <= 0.10 m |
| First-pose aligned orientation | Maximum rotation error <= 3 degrees; report p95 and maximum, not just translation ATE |
| One-second relative motion | Translation RMSE <= 0.03 m; rotation RMSE <= 1 degree, matched time horizon within one source frame |
| Path length | Estimated / evaluator camera-path length within [0.8, 1.2] |
| Finalization | Complete optimized pose history, clean shutdown; failed runs cannot save accepted SDK map |

A complete diagnostic run that bypasses the guard is useful evidence only. If any repeat fails, Gate A fails; do not promote its pretty surface. Passing Gate A means **short tracking feasibility**, not loop closure, floor separation, a room map, or navigation readiness. Its 3-degree tolerance is deliberately too loose for a room map: at 4 m, 1 degree alone displaces geometry about 7 cm.

### Gate B: repeatable closed-loop map

Use actual captured fixed-neck motion through a visually informative route, including at least one return to a previously observed area with changed viewpoint. Require three independent estimator runs, no dropped invalid spans, and post-shutdown complete optimized history. SDK LC/PGO events must be deduplicated by event timestamp; a successful event alone proves nothing.

For every repeat: first-pose aligned position p95 <= 0.03 m and max <= 0.05 m; orientation p95 <= 0.5 degree and max <= 1 degree; one-second RPE translation <= 0.03 m and rotation <= 1 degree; endpoint relative-pose error <= 0.05 m / 1 degree. Compare local, immediate, and final optimized trajectories: final optimization may not introduce a material worsening (> 0.01 m translation RMSE or > 0.25 degree rotation RMSE) or a broken seam. These are local map targets; choose and report the evaluated mapping range, initially <= 2 m. Wider mapping range must meet the geometric budget below.

Evaluate overlapping surface observations from separated visits using the same final trajectory, with **no per-visit ICP alignment**: plane-normal point distance p95 <= 0.03 m, max <= 0.05 m after explicitly defined sensor outlier exclusion; separately report rejected fractions and completeness. Hold out at least one revisited surface from tuning. Judge all repeats. Never convert this into “zero error” or guaranteed perfect geometry.

### Gate C: real floor-separated product

Deliver `obstacles.ply`, `uncertain.ply`, `ground.ply`, classified original keyframes, final estimated trajectory, and a JSON report of provenance, counts, source hashes, map status, and all quality gates. The obstacle file contains only measured points with validated OBSTACLE labels. Ground and uncertainty remain recoverable. A point-cloud artifact is the smallest complete 3D map delivery; an obstacle-only mesh is optional only after its component filtering/smoothing is shown to retain low/thin objects.

On synthetic regression fixtures: every labeled obstacle survives export, confirmed floor contributes zero points to obstacle export, mixed-label voxels preserve both obstacle and uncertain observations, 2 cm objects remain uncertain/blocked, 3 cm objects remain obstacles, and missing depth remains missing. On held-out measured observations with evaluator-only geometry labels: removed floor precision >= 99.5%; obstacle retention >= 99% for observed objects >= 2.5 cm; ground recall >= 90% on valid, visible floor. Report the denominator and frame coverage; do not hide incomplete classification by excluding uncertain floor from the recall denominator. Report uncertain proportion and observed-area completeness. Failing floor recall means an incomplete floor-free map, not permission to erase uncertainty.

Obstacle-only viewing may be the default, but visible status must say “obstacles only; uncertainty retained separately”; provide the uncertainty layer and keep it active in navigation checks. Three layers hidden in a viewer are not equivalent to an exported obstacle product.

### Gate D: costmap then navigation

Existing model: wheel radius 0.035 m, wheel lateral outer extent about 0.1326 m from body center (0.0812 + 0.0212 + 0.0177 + 0.0125); body box half-length 0.096648 m with x offset 0.015 m. These dimensions support retaining the existing **at least 0.25 m** navigation inflation, but do not establish the full swept radius under tilt/head/leg movement. Review must calculate that swept radius from collision geometry at the commanded posture before driving.

Require `clearance >= swept_radius + maximum_position_error + range * sin(maximum_heading_error) + maximum_surface_error + grid_discretization_allowance`. Use measured upper errors and conservative grid allowance; increase clearance if necessary. Do not force measured errors to fit 0.25 m by reducing margins. Navigation grid remains 0.05 m resolution with unknown and obstacles blocked; free space needs original valid depth rays and independent floor-support views. No orphan floor mask becomes proof of clearance.

Before native driving, require a connected inflated free region containing start/goal and a nontrivial >= 1 m path. Then one owned simulator trial, three repeats, zero collision contacts with the environment, goal error <= 0.10 m, live localization/staleness/depth guards active, and safe stop on injected loss. A kinematic RViz route stays demo-only.

### Conditional ToF anchoring ablation

The reviewer isolated a concrete earlier failure: old 5 Hz frame 500 has all 64 ToF zones valid, ranges 0.278–0.294 m, while raw DELTAR depth statistics are about 0.694/0.729/1.806 m. `depth_support.tof_support` accepts candidate patch depths only within `max(0.2 m, 3 sigma)` of a ToF return and caps additive correction at 0.15 m. For this mismatch it finds no eligible anchors and returns no supported depth. This explains rejection for that input; it does **not** establish that increasing the radius/cap produces geometrically correct depth, or that this caused all tracking failures.

**Executed and rejected:** the bounded global-scale ablation yielded only 1/12 usable old-cohort cases and 0/12 fixed-neck cases, primarily insufficient eligible training zones. This is inadequate evidence for a production change. Keep production `tof_support` unchanged; do not lower anchor requirements to manufacture acceptance. The protocol below remains the record of the tested hypothesis, not the next action to repeat unchanged.

Protocol:

- Freeze three cohorts from the old prepared measurements: all-zero-depth frames including 500, nonzero but biased neighbors, and well-supported control frames. Select at most 12 frames initially, spanning near/far and single/mixed-surface zones; hold out half the valid zones per frame using alternating checkerboard zone indices. Use identical RGB/predictions/ToF/calibration for every variant; no new inference is needed when prediction PNGs remain available.
- Baseline: current support unchanged. Record raw fusion bias, candidate anchor counts per zone, fraction reaching the 0.15 m clip, post-support valid fraction, and range-binned held-out ToF residual. Compute residual in ToF optical-Z coordinates using the full existing RGB-to-ToF transform, not a direct RGB-depth-minus-range subtraction.
- Diagnostic candidate: fit one positive global depth scale `s` to low-spread (reported sigma <= 0.02 m), single-surface training zones by robustly minimizing `median(abs(s * a_zone + b_zone - tof_mean))`, where `a_zone` is the median predicted RGB-ray contribution to ToF optical Z and `b_zone` is the calibrated translation contribution. Reproject scaled points into ToF zones before the final residual calculation because the RGB/ToF baseline makes zone membership depth-dependent; initial rectangle membership alone is insufficient. Require at least 12 training zones spanning both image axes, finite positive scale, and no oracle depth. Reject zones with competing returns/discontinuities. This tests a scale/bias hypothesis; it is not per-zone replacement with a constant plane. Compare against an additive-only fit as a diagnostic if scale residuals indicate a different model.
- Apply a candidate correction only in the diagnostic branch, then run the **unchanged** `tof_consistency_mask` and original validity mask; no invalid/zero pixel may become valid merely through filling, no zone rectangle is filled with its mean, and no support thresholds increase. Any broader correspondence needed for the scale fit must be validated on held-out zones, not licensed by a closer-looking map.
- Candidate passes the ablation only if held-out median residual improves by >= 50%, held-out p95 residual remains <= `max(0.02 m, min(0.05 m, 3 * reported_sigma))` per zone, valid support increases on the failed cohort, and control-frame p95 residual does not worsen by > 0.01 m. Separately score true surface-depth bias and foreground-edge retention in the offline evaluator, including a thin-object/mixed-return fixture; uncertainty must remain for ambiguous correspondence. Report near/far separately, since a global fit may hide one failing range.
- A successful ablation earns one isolated change to `depth_support.py` plus its tests and unchanged-caller verification in replay/live/reconstruction; it earns no map acceptance. Repeat all three native tracking runs and held-out geometry checks. If it fails, preserve rejection and investigate DELTAR preprocessing/intrinsics/calibration or train-time range mismatch; do not keep adding correction freedom.

The existing sensor configuration has no added random ToF noise. Any accepted anchoring must later be tested with calibrated noise/mixed surfaces before hardware use; this simulation experiment alone cannot validate that claim.
